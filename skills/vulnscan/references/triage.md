# 指摘の見分け方（本物か誤検知か）

vulnscan のルールは「書き方」に当たるだけなので、次の観点でコードを読んで決める。
迷ったら「要確認」にして、何が分かれば決まるかを書く。

## 秘密（SEC-*・FILE-*）

- **本物の形か**: 接頭辞と長さ（`AKIA` + 16 文字、`ghp_` + 36 文字、`sk_live_` など）。汎用の SEC-013・015・016 は値が意味のある文字列か
- **誤検知になりやすいもの**:
  - テスト・フィクスチャの固定値。テストのパスにある SEC-012・013・015・016 は、もともと「低」で出る。
    テストのパスは、フォルダが `tests/`・`test/`・`__tests__/`・`spec/`・`fixtures/`・`mocks/`・`__mocks__/`・`examples/`・`e2e/`・`integration_test/` など、
    ファイルが `*.test.*`・`*.spec.*`・`*_test.*`・`test_*`・`*Test.java` など
  - ドキュメントやサンプルの例、明らかなダミー（`xxx`・`example`・`changeme`・`your-...`）
  - **公開する前提の値**: Firebase の `apiKey`、Stripe の `pk_`、Supabase の anon key、地図の API キー。
    これらは「露出」ではないが、制限（HTTP リファラ・API の制限・RLS）が掛かっているかは別に確認する
- **FILE-003（`NEXT_PUBLIC_` などの値）**: 本当に秘密か。秘密ならブラウザに配られている（ビルドし直しても、古い JS が CDN に残ることがある）
- **SEC-012（DB の接続 URL）**: `localhost`・`docker` の開発用か、本番のホストか
- **テスト・デモの固定値は、どこで使われるかで決める**（パスがテストかどうかではなく）:
  - 手元やエミュレータ（`localhost`・`10.0.2.2`）だけで使う → 誤検知。接続先がそこに限られていることをコードで確かめる（コメントだけに頼らない）
  - 共有のクラウド環境（開発・検証の環境も含む）にアカウントやデータを作るスクリプト → 要確認。
    その環境に本物のデータがあるか、今もそのアカウントがあるかが決め手。リポジトリを読める人は誰でもそのアカウントで入れる
  - 本番に作る → 本物
- **本物の秘密が git に入っていたら、本物として扱う**: ファイルを消しても履歴から読める。直し方は「失効 → 再発行 → 環境変数へ」の順。
  （テスト・デモの固定値は上の決まりで判断する。git に入っているだけで本物にはしない）

## インジェクション（INJ-*）

- **eval / new Function（INJ-001・002）**: 引数が定数か。外からの入力（リクエスト・URL・フォーム・外部 API の応答・ユーザーが書ける DB の値）から来るか、呼び出し元までたどる
- **コマンド実行（INJ-003〜007）**: コマンドの文字列に変数が入るか、その出どころ
  - 固定のコマンド（`git rev-parse HEAD` など）は誤検知
  - ビルド用・開発用のスクリプトで、入力が自分の設定だけなら「低」に下げてよい（理由を書く）
- **SQL（INJ-008・009・014・018〜022）**: 値がプレースホルダ（`?`・`$1`・`%s`・`:name` とパラメータ）で渡っているか
  - テンプレートに入るのが定数や、許可した識別子（列名の一覧から選んだもの）だけなら誤検知。`= #{x}` の `x` が列名のこともある
  - ORM のタグ付きテンプレート（Drizzle の `` sql`…${x}` ``、Prisma の `` $queryRaw`…` ``）は値をパラメータにするので安全。`$queryRawUnsafe`・`sql.raw()`・`knex.raw` に文字列を組み立てて渡すのは危険
  - 同じ名前でも安全なものと危険なものがある: EF Core の `FromSql($"…{x}")`・`ExecuteSql` は補間した値をパラメータにするので安全、`FromSqlRaw($"…{x}")` は危険。WordPress は `$wpdb->prepare` を通したものが安全
- **デシリアライズ（INJ-010〜013・023〜025）**: 読むデータの出どころ。自分が書いたキャッシュだけなら低い、外から来るなら本物
  - `ObjectInputStream`（INJ-023）: `ObjectInputFilter` か `resolveClass` で読むクラスを絞っているか
  - `BinaryFormatter` など（INJ-024）: 出どころに関わらず置き換えを勧める（Microsoft は安全に使う方法が無いとしている）
  - `TypeNameHandling`（INJ-025）: 外から受け取った JSON を、その設定で読むか。`SerializationBinder` で許す型を絞っているか

## XSS（XSS-*・CFG-011）

- **dangerouslySetInnerHTML（XSS-001）**: 中身の出どころで決める
  - `JSON.stringify` の JSON-LD: 値に `</script>` が入ると抜けられる。`<` をエスケープしているか（`.replace(/</g, "\\u003c")`）
  - CMS の本文: CMS に書ける人を信頼するか、サニタイズ（DOMPurify など）しているか
  - ユーザーの入力: 本物
- **innerHTML（XSS-002）・v-html・document.write**: 入れる値の出どころ。定数やエスケープ済みなら誤検知
- **dangerouslyAllowSVG（CFG-011）**: 最適化を通す画像に、ユーザーがアップロードした SVG が入るか
- **Blade の `{!! !!}`（XSS-007）**: 出す値の出どころ。ユーザーが書いた HTML なら、保存か表示のときにサニタイズ（HTMLPurifier など）しているか。
  置き換えつきの `trans('…', ['name' => $x])` は置き換えの値がエスケープされないので、`$x` を `e()` で包んでいるか

## 暗号・乱数（CRY-*）

- **MD5 / SHA1**: 用途で決める。パスワードの保存・署名・改ざん検知なら本物。キャッシュのキー・ETag・ファイルの重複検知なら誤検知
- **Math.random / random（CRY-004・005）**: 作った値の用途。トークン・リセットのリンク・セッション・招待コードなら本物。表示用の ID・アニメーションなら誤検知

## 通信・認証（TLS-*・AUTH-*）

- **TLS の検証を切る（TLS-*）**: 本番で通るコードか。テスト・ローカル専用の分岐（環境変数で切り替え）なら低いが、本番に漏れないかを見る
- **jwt.decode（AUTH-003）**: decode の結果を認可の判断に使っているか。表示だけなら誤検知
- **CORS のワイルドカード（AUTH-004）**: Cookie などの認証情報で動く API か。認証なしの公開データだけなら誤検知
- **CSRF の無効化（AUTH-005）**: 状態を変える道か。署名で守っている Webhook の受け口、Cookie のセッションを使わない API（トークンで認証する）、OmniAuth の callback なら誤検知
- **一括代入（AUTH-009・AUTH-010）**: `permit!` した値や、`$guarded = []` のモデルに、リクエストの値をそのまま `create`・`update`・`fill` で渡しているか。
  検索の条件として読むだけ（保存しない）なら誤検知。保存するなら、role・admin・user_id・tenant_id などを書き換えられないかを見る

## 設定・CI（CFG-*・CI-*）

- **CFG-***: 本番の設定か、開発用の設定ファイル・分岐か
- **Actuator（CFG-019）**: Spring Security で `/actuator/**` にログインとロールを求めているか。`permitAll()` か、Spring Security が無いなら本物
- **docker.sock（CFG-020）**: Traefik・Portainer など、Docker を操作するのが仕事のコンテナか。それでも、そのコンテナを乗っ取られるとホストの root と同じなので、ソケットのプロキシで API を絞ることを勧める
- **ホストの共有（CFG-021）**: 監視のエージェント・ingress controller など、ホストのネットワークやプロセスが要る用途か
- **nginx の alias（CFG-022）**: alias のフォルダの 1 つ上に、読まれて困るもの（設定・ソース・`.env`）があるか
- **CI-001**: `run:` に埋めている値が、PR を出す人が自由に書ける文字列か（タイトル・本文・ブランチ名・コミットのメッセージ）
- **CI-002**: checkout した PR のコードを、secrets を使えるジョブで実行しているか（ビルド・テスト・`npm install` も実行に当たる）

## 依存（DEP-*）

- **DEP-001**: 実行時の依存か、開発時だけか（npm なら `npm ls <名前>` で経路を見る）。修正版があるか。脆弱な機能を実際に使っているか
- **DEP-010 / 011 / 012**: 依存は調べられていない。本物でも誤検知でもなく「見ていないもの」に書く
